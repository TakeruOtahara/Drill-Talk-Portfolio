# Day 1: 開発環境の構築と疎通確認
**日付:** 2025/12/31
**目標:** Next.js (Frontend) と FastAPI (Backend) を連携させ、Hello Worldを表示する。

## 📝 実施内容
1. **プロジェクト構成の決定**
   - フロントエンドとバックエンドを分離したマイクロサービス構成を採用。
   - Frontend: Next.js (TypeScript, App Router)
   - Backend: Python (FastAPI)

2. **環境構築**
   - Python仮想環境 (venv) のセットアップ。
   - Node.js のインストールと Next.js プロジェクトの作成。
   - VS Code での開発環境整備。

3. **疎通確認 (Hello World)**
   - FastAPI で `localhost:8000` にAPIを作成。
   - Next.js から `fetch` でAPIを叩き、CORS設定を行って通信に成功。

## 🐛 発生したエラーと解決策 (トラブルシューティング)
### 1. `npx` コマンドが見つからない
- **状況:** フロントエンド作成時に `npx create-next-app` を実行したらエラー。
- **原因:** Node.js がインストールされていなかった。
- **解決:** Node.js 公式サイトから推奨版 (LTS) をインストールし、VS Codeを再起動した。

### 2. `uvicorn` が認識されない
- **状況:** 新しいターミナルでバックエンドを起動しようとしたらエラー。
- **原因:** 仮想環境 (venv) に入っていなかったため。
- **解決:** `.\venv\Scripts\Activate.ps1` を実行して venv を有効化してから実行した。

### 3. Gitの管理場所のズレ
- **状況:** `frontend` フォルダ内に不要な `.git` が生成され、親フォルダでの管理と競合した。
- **解決:** 子フォルダの `.git` を削除し、親フォルダ (`Drill-Talk-Portfolio`) で `git init` をやり直した。

## 💡 今日の学び・感想
- 環境構築はコードを書く以前の難関だったが、エラーログを読んで一つずつ対処すれば動くことがわかった。
- フロントとバックエンドを同時に動かすときは、ターミナルを2つ開いておく必要がある。

# Day 2: フロントエンド音声入力の実装
**日付:** 2026/01/01
**目標:** ブラウザのマイクAPI (MediaRecorder) を使用して、ユーザーの声を録音・再生する。

2. **UI実装**

   - 録音完了後にオーディオプレーヤーを表示し、即座に確認できるようにした。

## 💡 今日の学び
- Reactの `useRef` を使うことで、再レンダリングさせずに録音データ（チャンク）を保持できることを学んだ。
- ブラウザのセキュリティ制約により、マイク使用にはユーザーの許可が必須であることを確認した。

# Day 3: フロントエンドからバックエンドへの音声送信
**日付:** 2026/01/01 (Day 3)
**目標:** 録音した音声データ (Blob) を FastAPI サーバーに送信し、ファイルとして保存する。

## 📝 実施内容
1. **バックエンド (FastAPI)**
   - `/talk` エンドポイントを作成。
   - `UploadFile` 型を使用して、フォームデータとして送られたバイナリデータを受け取る処理を実装。
   - `shutil` ライブラリを使ってサーバーローカルに `received_audio.wav` として保存成功。

2. **フロントエンド (Next.js)**
   - `MicButton` コンポーネントに送信機能を追加。
   - `FormData` オブジェクトを作成し、録音データ (Blob) を格納して POST 送信。

## 💡 今日の学び
- 音声データのようなバイナリファイルを送る際は、JSONではなく `FormData` (multipart/form-data) を使う必要があることを学んだ。
- Python側では `UploadFile` を使うことで、メモリを圧迫せずに大きなファイルも扱える設計になっている。

## 🔜 Next Step
- Day 4: 保存した音声ファイルを Gemini API に送信し、AIからの返答（テキスト）を受け取る。

# Day 5: 音声合成 (TTS) の実装と「会話ループ」の完成
**日付:** 2026/01/03 (Day 5)
**目標:** AIのテキスト応答を音声データ (MP3) に変換し、フロントエンドで再生させる。

## 📝 実施内容
1. **バックエンド (FastAPI)**
   - `gTTS` (Google Text-to-Speech) ライブラリを導入。
   - 生成された音声データをメモリ上 (`io.BytesIO`) で処理し、ファイル保存せずに直接 `base64` 文字列にエンコードしてJSONレスポンスに含めた。
   - これにより、ディスクI/Oの遅延を回避し、レスポンス速度を向上させた。

2. **フロントエンド (Next.js)**
   - APIから受け取った `base64` 文字列を `new Audio("data:audio/mp3;base64,...")` で再生するロジックを実装。

## 💡 結果
- ユーザーが話しかけると、マナブ（AI）がテキストと音声の両方で応答する「会話のキャッチボール」が成立した。
- "トランシーバー方式"（録音→送信→再生）ではあるが、基本機能は全て動作している。

# Day 8: WebSocket実装とリアルタイム通信基盤の構築
**日付:** 2026/01/06 (Day 8)
**目標:** HTTP (REST API) を廃止し、WebSocketによる双方向通信を実装して、リアルタイム会話の基盤を作る。

## 📝 実施内容
1.  **バックエンド (FastAPI)**
    - `/ws` エンドポイントを作成し、`WebSocket` プロトコルをサポート。
    - `ConnectionManager` クラスを実装し、クライアントとの永続的な接続を管理。
    - 受信ループ (`while True`) 内で音声データを受け取り、即座にAI処理→音声合成を行って返すフローを構築。

2.  **フロントエンド (Next.js)**
    - カスタムフック `useDrillSocket` を作成し、接続・切断・再接続のロジックを分離。
    - `MicButton` コンポーネントを改修し、明示的な「送信ボタン」を廃止。録音停止トリガーで即座にデータストリームを送信する「Push-to-Talk」方式へ移行。

## 💡 成果
- サーバーとのハンドシェイク時間が削減され、レスポンス速度が向上した。
- ユーザーのアクション数が減り（送信クリック不要）、体験がスムーズになった。

## 🔜 Next Step
- **Day 9: VAD (Voice Activity Detection) による完全ハンズフリー化**
- 「録音ボタン」すらもなくし、ユーザーが話し始めれば勝手に送信される「本物のリアルタイム会話」を実現する。
# Day 9: VAD実装と完全ハンズフリー授業の実現
**日付:** 2026/01/07 (Day 9)
**目標:** 授業開始ボタンを押した後、ユーザーが操作することなく自然な会話ができる「完全ハンズフリー機能」を実装する。

## 📝 実施内容
1.  **VAD (音声区間検出) の自作 (`useVAD.ts`)**
    - `Web Audio API` の `AnalyserNode` を使用してマイク入力の音量 (RMS) をリアルタイム監視。
    - 閾値を超えたら録音開始、無音が一定時間続いたら録音停止＆送信というロジックを実装。
    - `AudioContext` のクローズ処理における多重呼び出しエラー (`InvalidStateError`) もハンドリング済み。

2.  **授業管理コンポーネント (`Classroom.tsx`)**
    - 20分間のカウントダウンタイマーを実装。
    - 授業中のみ WebSocket と VAD を有効化し、終了後は自動的に切断するリソース管理を行った。
    - 音量に応じて背景が波紋のように動くビジュアライザーを実装し、マイクが反応していることを視覚的に伝えた。

## 💡 成果
- ユーザーはボタンを押す必要がなく、対面で話しているような自然な会話体験（フリートーク）が可能になった。
- "Push-to-Talk" から "Voice-Activated" への移行に成功し、UXが劇的に向上した。
